1. Standalone Template Proliferation

Files

15 of 19 Buyer templates are standalone HTML:
cart, chat, checkout, dashboard, favorites, loyalty, order-detail, order-success, orders, products, profile, promo, reviews, settings, wallet

Problem

Each standalone page duplicates <head> with fonts, icons, Tailwind CDN, token.css, and JS setup. Only 4 pages (product-detail, refunds/*) extend base.html. Every new page must copy the same scaffolding — low leverage, high maintenance burden.

Solution

Make all Buyer pages extend base.html, using Django's {% block %} system for content, scripts, and styles. This eliminates 15× duplication of head/meta/Tailwind/favicon and gives every page the shared scroll-reveal system, grain overlay, and premium.css automatically.

Benefits

Locality: Head, nav, footer, mobile-nav, toast live in one file. Leverage: A single change to base.html propagates to all 15 pages. Testability: Consistent structure makes regression testing predictable.

2. Inline JS/CSS Duplication

Files

All 15 standalone Buyer templates + 9 page-specific JS files in static/js/pages/buyer/*/script.js

Problem

showToast() is defined 12 times across JS files. Auth-check logic (profile dropdown toggle, logout handler, auth/guest toggle) is repeated in 8+ templates. CSS selectors like .skeleton-card-premium, shimmer keyframes appear in 5+ pages. Deletion test: delete any page's inline JS, other pages still work — no module earns its keep.

Solution

Consolidate showToast into existing utils/toast.js. Extract auth/DOM setup into utils/auth-ui.js. Extract shared card/shimmer patterns into premium.css (partially done). Each page's inline JS then only contains page-specific logic.

Benefits

Locality: Toast styles in one place. Auth UI in one place. Leverage: Fix a toast bug once, not 12 times. Deletion test passes: Delete old inline toasts, complexity vanishes, utility remains.

Before: 12 copies of showToast
cart/script.js:  function showToast(text, type) { ... }
checkout/script.js:  function showToast(text, type) { ... }
wallet/script.js:  function showToast(text, type) { ... }
seller/ulasan/script.js:  function showToast(msg, type) { ... }
...8 more files...
After: One shared utility
utils/toast.js:  function showToast(msg, type) { ... }
→ Imported once in base.html
→ All pages call showToast() without redefining
Worth exploring

3. CSS Fragmentation & Overlap

Files

tokens.css (7KB), components.css (15KB), style.css (8KB), premium.css (12KB), pages/buyer/home/style.css (39KB!)

Problem

4 core CSS files (42KB) with unclear seams. style.css is legacy monolithic. components.css overlaps with style.css. premium.css overlaps with components.css. Page buyer/home/style.css (39KB) is larger than any core file — contains layout, cards, animations, responsive — should be shared. Interface (file boundaries) is as complex as implementation.

Solution

Clear seams: tokens.css = variables only. components.css = shared components. premium.css = premium components. style.css = legacy aliases. Move shared layout/card styles from buyer/home/style.css into appropriate core files.

Benefits

Depth: Each file has clear responsibility. Leverage: Card styles in one place. Locality: Know which file to edit for a button vs layout change.

Worth exploring

4. Inconsistent Layout Shells

6 pages use different layout classes: .page-shell, .dashboard-shell, .profile-layout, .app-shell, .orders-grid-layout. Each re-implements grid dimensions, spacing, max-width. If sidebar width changes, 7+ files must update. Solution: ONE layout system in components.css with modifier classes for variations.

Speculative

5. Shared JS Auth UI Behaviors

Every page's DOMContentLoaded duplicates ~60 lines of auth check, profile dropdown toggle, logout binding, search binding, and geolocation. ~900 lines of identical logic across 15 pages. Extract into utils/auth-ui.js with initAuthUI(), call once from base.html. Net savings: ~840 lines removed.

Strong

6. Sidebar/Topbar Include Inconsistency

6 pages use {% include %} for sidebar/topbar, but 9+ still have inline HTML (Dashboard, Cart, Orders, Profile, Checkout, etc.). Each inline copy = 80-150 lines of identical markup.
